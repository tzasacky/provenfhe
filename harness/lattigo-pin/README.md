# lattigo-pin: Lattigo v6.2.0 BGV against the phase contracts, at the Lattigo profile

The second library instance of the profile interface (`Challenge/Profile`). The proved part is in
`Challenge/Instances/Lattigo.lean` (coverage at Lattigo's parameters, achievability by the proved
algorithm families, certificates at the profile). This directory is the **executed evidence** that
Lattigo's own code stays within that profile on recorded runs.

| path | what |
|---|---|
| `FORMAT.md` | the dump format `lattigo-pin/v1` (one JSON file per case) |
| `export/` | Go exporter (Lattigo v6.2.0 from the module cache, commit `c1fd095f`); `export/gen.sh` writes the suites |
| `lean/LattigoPin.lean` | the checker, run with `lake env lean --run` (no Lake target) |
| `lean/summarize.py` | tables from the result lines (untrusted statistics) |
| `fixtures/` | 8 recorded honest cases (2 per parameter set) |
| `fixtures-defects/` | 15 recorded cases (suites `scale`, `defectB`, `defectN`) for the three defects reported upstream as public tuneinsight/lattigo issues: #597 (scale metadata lost by scalar operations: `scale`), #599 (key switching without special primes: `defectB`) and #600 (base-2 digit count: `defectN`) |
| `run.sh` | check `fixtures/` (or a directory given as argument); exits 1 iff a phase check fails, which the defect cases do by design |
| `out/` | (not committed) default output of `export/gen.sh` |

## What is checked, and with what

Lattigo's BGV is MSB-form; every recorded limb is multiplied by `t mod qᵢ` (the *t-reading*,
`Challenge/Instances/Lattigo/Defs.lean`) and CRT-reconstructed, which gives textbook BGV
ciphertexts. Then, per recorded operation:

* `add`, `sub`, `mul` (tensor, 3 parts), `mulConst`, `relin`, `rescale` (= `modSwitch`, also of
  3-part products), and rotations as the composite `automorph g; keySwitch` (the intermediate is
  `σ_g` of the operand's components; Lattigo key-switches first and applies the automorphism after,
  so the intermediate is synthesized, not recorded): the decision `FHE.Pin.stepOKb` of
  `Spec.Trace.StepOK`, proved sound (`FHE.Pin.stepOKb_sound`), on phases built by the forced
  `phaseAtZ`/`centredA` (proved equal to `Spec.Trace.phaseAt` and its centred lift), at the budget
  `Challenge.Instances.Lattigo.profile` of the case's parameters (computed, never read from input);
* fresh encryptions (`enc.fresh`): the forced centred phase within `skFresh` / `pkFresh` and
  congruent to the stored plaintext modulo `t` (a direct computation, no proved decision);
* `user.decoded` (outside every contract): Lattigo's `Decrypt`+`Decode` under its tracked scale
  against the exporter's cleartext evaluation.

**Not covered by a theorem**: JSON loading, the CRT step (checked against every limb), the
t-reading, the operand lookup (`GetOK`: this driver does not replay `Spec.Source.step`; levels, keys
and numbers of components are the recorded ones), the rotation intermediate, the fresh-encryption
and decoded-value lines. This is weaker than `openfhe_pin`, which replays the extracted program.
For `base2 ≠ 0` (defect suite N only) the key-switching budget is the canonical-representative
hybrid bound with one limb per digit, an argued (not proved) upper bound for correct base-2
decomposition.

## Results (143 cases, generated by `export/gen.sh`; N = 16 or 32)

Lattigo's key and encryption randomness is not seeded, so a regeneration gives other bytes (and the
same verdicts, on the three regenerations made). The honest programs run their multiplication chain
as deep as noise allows: by default a step that would bring any ciphertext to `|t·phase| ≥ Q_ℓ/4` is
discarded (17 of 128 cases). Because that filter could also drop a key switch far above budget, the
honest suite was re-recorded with `export -nofilter` (every step kept, failures only noted; 20 of
128 cases contain a step the filter would have dropped): 128 cases, 5504 phase checks, **0
violations** (max measured/budget: relin 2^-3.6, keySwitch 2^-3.4, rescale 2^-1.3, encPk 2^-1.1,
encSk 2^-0.6); 2 decoded values wrong, both from noise exhaustion, not a contract violation.
